# ADR-0005: Транспорт сессии и делегирование ролей

- Статус: **Approved**
- Версия решения: 1.0.0
- Владелец решения: владелец проекта
- Утверждено: владельцем проекта (2026-09-09)
- Замещает: открытые пункты ADR-0002 в разделе «Риски и открытые решения»
- Связанные требования: FR-019..022, FR-024, FR-028, NFR-002..004

## Контекст

Ядро должно однозначно определить транспорт credential, срок жизни сессии и безопасное делегирование ролей. Клиентские данные не являются источником полномочий. Изменения должны сохранять атомарность назначения, отзыва сессий и аудита.

## Решение

Cookie-транспорт использует `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, без `Domain`. В cookie передается 64-символьный hex credential; в PostgreSQL хранится только SHA-256 hash. Cookie-политика не отменяет CSRF-защиту.

Сессия имеет absolute TTL 8 часов и idle TTL 30 минут. Успешная проверка `AuthorizationFacade.authorize()` при действии пользователя считается активностью. Idle deadline продлевается не чаще одного раза в 5 минут и никогда не превышает `expires_at`. Реализация использует условное обновление без новой миграции: фоновые, polling и keepalive-запросы не считаются активностью и не продлевают сессию. Ошибка продления не превращает уже разрешенную операцию в отказ.

Новый credential выдается при login и изменении набора прав. Существующее `revokeAllForEmployee` при `assignEmployee` сохраняется как принудительная ротация.

Для мутирующих Server Actions и Route Handlers обязательна double-submit CSRF token либо серверная проверка `Origin`/`Sec-Fetch-Site`; `SameSite=Lax` недостаточен. Login ограничивается по паре «учетная запись, источник» с экспоненциальной задержкой, а ответы не различают отсутствие пользователя и неверный пароль. LDAP connect/bind/search имеют конечные конфигурируемые таймауты и проверку сертификата LDAPS/StartTLS.

Оператор с `employees.manage` может добавлять или снимать только роли, объединенный набор разрешений которых является подмножеством его собственных разрешений. Проверяется дельта ролей, то есть только добавляемые и удаляемые роли; неизмененные роли сотрудника не блокируют смену отдела. Это позволяет оператору сменить отдел сотруднику, уже имеющему роль выше полномочий оператора, не позволяя выдать или снять новую привилегию сверх его прав. Правило `platform.admin` остается частным случаем с требованием владения этой ролью. Самоназначение через `assignEmployee` полностью запрещено.

Последний пригодный администратор MVP определяется как активный сотрудник с ролью `platform.admin`; снятие роли у последнего дает `CONFLICT` и сохраняет инвариант.

`resourceScope` остается неподдерживаемым (`allowed: false`) до отдельного доменного контракта.

## Открытые решения

Остаются открытыми lifecycle отделов и ролей, retention аудита и resource scope. Формат CSRF token, численные rate limits и LDAP timeout configuration реализуются на этапе 2 в server boundary.

## Последствия и риски

Продление добавляет условный round-trip к успешной авторизации. Параллельные запросы одной сессии могут одновременно попасть в окно продления вне транзакции; `LEAST` и условия `WHERE` сохраняют инвариант. Правило по дельте позволяет сохранять уже имеющуюся более широкую роль, что является осознанным компромиссом для смены отдела. Ужесточение делегирования ломает старое поведение выдачи широких ролей и приемлемо для MVP без эксплуатационных установок.
